## 프로젝트 소개

테마파크는 시간대·장소별로 방문객 밀도가 크게 달라지고, 그에 따라 응급상황(부상·사고·건강 이상) 발생 위험도 함께 변합니다. 하지만 안전관리 인력은 한정되어 있어 모든 구역을 동시에 촘촘히 관리하기 어렵습니다.

이 프로젝트는 **방문객 밀도·기상 조건·시설 특성 데이터로 응급상황 발생 확률을 사전에 예측**하고, 위험도에 따라 **순찰 주기·필요 인력·대응 프로토콜을 자동으로 추천**해 안전관리자의 의사결정을 돕는 것을 목표로 합니다.

| 항목 | 내용 |
| --- | --- |
| 데이터 기간 | 2025-08-01 ~ 2026-07-31 (1년) |
| 총 레코드 | 21,900건 (시설 × 10시간/일 × 365일) |
| 응급 발생률 | 3.82% (836건) |
| 데이터 성격 | 시뮬레이션 기반 가상 데이터 (실제 배포 전 프로토타입 단계) |

## EDA 주요 발견

- 계절별 응급 발생률: 여름 > 가을 > 봄 > 겨울
- 시간대: 13시·15시에 방문객·사고 모두 피크 (`is_peak_hour` 피처로 반영)
- 폭염 시 응급 발생률이 일반 조건 대비 유의미하게 상승
- 강우 시 낙상 유형 응급 증가
- 밀도 0.6 초과 구간에서 위험도 급증

## 모델 아키텍처

3단계 캐스케이드 구조로 응급 발생 여부 → 유형 → 심각도를 순차 예측합니다.

```
입력 데이터 (28 피처)
        │
   ┌────▼────┐
   │ Stage 1 │  응급 발생 여부 예측 (이진 분류, LightGBM)
   └────┬────┘
        │ P(응급) ≥ 임계값
   ┌────▼────┐        ┌─────────┐
   │ Stage 2 │        │ Stage 3 │
   │ 응급 유형 │        │  중증도  │
   │(12종→5그룹)│       │ (3단계) │
   └────┬────┘        └────┬────┘
        └──────┬───────────┘
               ▼
   Isotonic 보정 확률 → 위험도 스코어
```

```
risk_score = P(응급) × (1 + E[중증도] / 5)
E[중증도] = P(경증)×1.0 + P(중등증)×2.5 + P(중증)×5.0
```

배포 버전(라이브 데모)은 실시간 추론 대신, 구역 × 혼잡도 × 조건 조합에 대해 미리 계산한 **룩업 테이블** 방식을 사용해 응답 속도를 확보했습니다.

## 모델 성능

클래스 불균형(3.82%)이 심해 ROC-AUC보다 **AP(Average Precision)를 핵심 지표**로 사용합니다.

| 지표 | 점추정 | 95% CI | 비고 |
| --- | --- | --- | --- |
| Stage 1 AP (Test) | 0.0845 | [0.060, 0.120] | 기저율(4.35%) 대비 **1.94배** |
| Stage 1 F1 (Test) | 0.190 | [0.131, 0.250] | |
| Stage 1 AUC-ROC | 0.672 | — | 참고용 보조 지표 |
| Stage 2 (12종) Macro-F1 | 0.294 | [0.178, 0.383] | 5건 미만 희귀 클래스 존재 |
| Stage 2 (5그룹) Macro-F1 | 0.334 | [0.235, 0.432] | 운영 알람용 권장 |
| Stage 3 중증도 Macro-F1 | 0.349 | [0.266, 0.418] | 중증 표본 6건, 보수적 해석 필요 |

확률 보정(Isotonic Regression)을 적용해 scale_pos_weight로 왜곡된 확률을 실제 발생률에 맞게 재조정했습니다. 보정 후 "위험" 등급 판정 건수가 49건 → 34건으로 감소했습니다.

## AI 대응 매뉴얼 & 자원 배치

위험도 스코어에 따라 4단계로 자동 분류합니다.

| 단계 | 스코어 | 주요 조치 | 필요 인력 |
| --- | --- | --- | --- |
| 🔴 위험 | ≥ 0.15 | 대응팀 즉시 파견, AED 준비, 119 연락 | 3명 이상 |
| 🟡 주의 | 0.07 ~ 0.15 | 30분 간격 예방 순찰, 취약자 모니터링 | 2명 |
| 🔵 관찰 | 0.03 ~ 0.07 | 60분 간격 표준 순찰, 기상 확인 | 1명 |
| 🟢 안전 | < 0.03 | 정상 운영 | 최소 |

**자원 배치 공식** (총 인력 N명 기준, 시설당 최소 보장 0.3명 + 위험도 비례 배분):

```
각 시설 배치 인원 = 0.3 + (해당 시설 위험도 / 전체 위험도 합) × (N - 0.3×N)
```

## 사전 계산 룩업 테이블

### 왜 사전 계산인가?

입력 공간이 **6 시설유형 × 4 혼잡도 × 2⁶ 조건 = 1,536가지**로 유한하기 때문에 전량 사전 계산이 가능합니다.

| 항목 | 실시간 추론 | **사전 계산 (채택)** |
| --- | --- | --- |
| 응답 속도 | ~10ms | **< 1ms** |
| 오프라인 동작 | 불가 | **가능** |
| 결과 일관성 | 버전 민감 | **스냅샷 고정** |
| 배포 복잡도 | 서버 필요 | **파일 복사만으로 완결** |

자세한 설계 근거는 [`design_rationale.md`](design_rationale.md)를 참고하세요.

### `ecofarm_risk_lookup.json` (2.3MB)

중첩 딕셔너리 구조로 O(1) 조회:

```python
entry = lookup["F01"]["매우혼잡"]["우천|폭염|피크타임"]
# 조건 키: 정렬된 조건명을 | 로 연결 (조건 없으면 "없음")
```

엔트리 필드: `risk_score`, `risk_level`, `risk_icon`, `p_emergency`, `p_severity` (경증/중등증/중증), `actions`, `staff`, `equipment`, `escalation`, `fac_note`

| 컬럼 | 설명 |

## 알려진 한계

이 프로젝트는 성능 수치를 부풀리지 않고 한계를 투명하게 공개하는 것을 원칙으로 합니다.

- **가상 데이터 기반**: 현재 모든 데이터는 시뮬레이션으로 생성되었습니다. 성능 지표는 실제 운영 환경의 예측력을 보장하지 않으며, 실제 사고 로그 확보 후 재검증이 필요합니다.
- **6개 시설 유형으로 학습**: 모델은 6개 시설 유형으로 학습되었습니다. 데모의 12개 표시 구역 중 같은 유형에 속한 구역(예: 오토캠핑장A/글램핑존)은 기본 위험도 점수가 동일하게 산출됩니다. 대응 조치·필요 장비 안내는 구역별 특성을 반영해 개별화했습니다.
- **소표본 신뢰구간**: 테스트셋 응급 사례가 81건뿐이라 Stage 2/3 지표의 신뢰구간이 넓습니다. 특히 5건 미만인 희귀 유형과 중증(6건)은 참고용으로만 해석해야 합니다.
- **한파 변수 미반영**: is_coldwave가 학습 기간 내 0건이라 상수 피처로 제거했으며, 추위 관련 위험은 temperature로만 간접 반영됩니다.
